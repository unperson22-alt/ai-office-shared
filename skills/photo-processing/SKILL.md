# SKILL: photo-processing

## Когда использовать
Когда бота учат обрабатывать присланные фото: фильтры, ретушь, фон, кроп под
Инсту, стикеры, апскейл, сжатие. Модуль общий — `ai_office_shared.shared.photo`.

Приём картинки (photo/document, группа/ЛС) — не здесь, а в `shared/media.py`.
Этот skill начинается с момента, когда байты уже на руках.

## Три слоя обработки

| Слой | Модуль | Что делает | Цена |
|---|---|---|---|
| 1. Адаптивные рецепты | `shared/photo_looks.py` | Меряет кадр (гистограмма, тени/света, насыщенность, доля кожи) и считает параметры под него. Рецепт задаёт цель, а не проценты | бесплатно, ~100–250 мс |
| 2. Арт-директор | `shared/photo_ai.py` | Модель смотрит на кадр и правит числа под сюжет. Картинку НЕ рисует — рендер локальный, в полном разрешении. Все её значения проходят через клампы | 1 запрос к Anthropic на фото, `PHOTO_AI_DIRECTOR=1` |
| 3. Перерисовка | `photo.ai_restyle` | Чужая модель рисует новую картинку по тексту | нейроны Cloudflare, лимит в день |

Ретушь стоит сбоку от этих слоёв: `shared/photo_retouch.py` — не фильтр, а
точечная операция. Она ищет маленькие пятна на коже и заменяет их окружением,
а не смягчает кадр целиком.

Слой 2 и 3 опциональны: выключены или недоступны — работает слой 1, и
пользователь получает обработанное фото, а не отказ.

## Ретушь: как она устроена и почему так

За один день 21.08.2026 ретушь провалилась трижды, и каждый провал — отдельный
урок:

1. Кнопка «🧴 Ретушь» вела в пресет «нежное» — размытие всего кадра.
2. Первая точечная версия прошла все тесты и превратила лицо в мыло: брови
   размазаны, ресницы съедены. Тесты гонялись на синтетическом лице из плоских
   заливок, где этот класс ошибки физически невидим.
3. Вторая версия, зажатая ради безопасности, вернула фото **без единого
   изменения**: она искала изолированные тёмные точки на гладком фоне, а
   настоящее «прибрати недоліки» — это пятнистость тона на пол-щеки.

**Что работает — частотное разделение**, то же, чем ретушируют в редакторах.
Кадр раскладывается на тон (низкие частоты: покраснения, пятна, неровный цвет)
и текстуру (высокие: поры, волоски, микрорельеф). Тон берётся сглаженный,
текстура — исходная, и они собираются обратно. Пятнистость уходит, кожа
остаётся кожей. Поверх — точечное лечение выраженных элементов медианой
окрестности.

Радиус тона привязан к стороне кадра (2%) и намеренно невелик: сильнее — и
вместе с пятнами уедет светотень, лицо станет плоским.

**Границы работы — маска кожи минус маска волос.** Волос отличается от дефекта
не темнотой: воспалённый прыщ тоже тёмный, и правило «темнее кожи — значит
волос» пометило волосами ровно все дефекты на лице (заход №3, ретушь честно
ничего не нашла). Отличает волос **текстура**: волос — десятки мелких перепадов
на пятачке, прыщ — гладкое плавное пятно. Маска волос собирается из трёх
признаков: плотная мелкая текстура сама по себе (брови любого цвета, включая
светлые), умеренная текстура плюс «темнее кожи», плотность плюс протяжённость.

Маска кожи — цветовой RGB-тест плюс тест по цветности YCbCr **только для тёмных
пикселей**: без ограничения по яркости он тянет в «кожу» деревянный шкаф на
фоне и половину кадра.

| Слова в чате | Что делает |
|---|---|
| «ретушь», «прибери недоліки» | дефекты + выравнивание тона, сила 0.8 |
| «ретушь сильнее», «зроби шкіру гладкою» | то же на полной силе |
| «чуть-чуть подретушируй» | вполсилы |
| «только прыщи», «тон не трогай» | без выравнивания тона |

Время: ~0.8 с на 900×1200, ~1.5 с на 1280×960.

Границы, которые не скрываем: морщины и крупные родинки не трогаем — они
крупные по построению; при очень тёмном кадре дефект тонет в шуме сжатия.

**Правило приёмки:** зелёные тесты на синтетике — не приёмка. Прогоняй на
настоящих фотографиях и смотри результат сам, в кропе, на бровях, ресницах и
бороде. И бери лица с настоящими дефектами, а не только с гладкой кожей: на
чистом лице любая ретушь выглядит успешной.

## Язык запроса

Синонимы в `_OP_ALIASES` / `_PRESET_ALIASES` — русские И украинские. Это не
украшение: Крисс отвечает и Владу, и Яне, а Яна пишет по-украински. Пока
«прибери недоліки» не совпадало ни с одним словом, `is_photo_request()`
возвращал False, просьба уезжала в LLM, и та отвечала «редактировать
изображения не умею» — при живом рабочем модуле. Добавляешь операцию — добавляй
оба написания сразу.

## Патч бота (PTB)

**1. requirements бота:** добавить `pillow>=10.0.0`.
Для работы с фоном дополнительно `rembg[cpu]>=2.0.50` — это ~200 МБ образа и
~530 МБ RSS, ставить только тем ботам, кому фон реально нужен (Крисс — да,
торговым ботам — нет). Отдельного флага «включить» не нужно: модуль сам видит
пакет. `PHOTO_REMBG=0` — наоборот, выключить, не выкидывая зависимость.

**2. Хендлер:**

```python
import base64
from ai_office_shared.shared.media import IMAGE_FILTER, extract_image, ImageError
from ai_office_shared.shared.photo import process_photo, PHOTO_HELP

async def handle_photo(update, context):
    img = await extract_image(update.message, context.bot)
    if isinstance(img, ImageError):
        await update.message.reply_text(img.user_message)
        return

    note = await update.message.reply_text("🎨 обрабатываю…")
    res = await process_photo(base64.b64decode(img.b64), img.caption)
    await note.delete()

    if res.error:
        await update.message.reply_text(res.error)      # молчать нельзя никогда
        return

    stream, filename = res.as_file()
    # document, а не photo: Telegram пережимает photo и съедает всю резкость
    await update.message.reply_document(document=stream, filename=filename,
                                        caption=f"✅ {res.caption}")

ptb.add_handler(MessageHandler(IMAGE_FILTER, handle_photo))
```

**3. Подсказка в /help бота:** добавить `PHOTO_HELP` — иначе пользователь не
узнает про фильтры и будет каждый раз получать автокоррекцию.

**4. Кнопки вместо угадывания слов** (как сделано у Крисс, `kriss-bot/bot.py`):
фото без подписи → сообщение с inline-меню, ничего не спрашиваем и в LLM не
ходим. Картинку в кнопку не положить — `callback_data` ограничен 64 байтами:
`file_id` кладётся в Redis под номером сообщения (TTL сутки), в кнопку идёт
только операция и номер. Обработчик кнопок регистрируется ДО общего
`CallbackQueryHandler`, иначе тот съедает нажатия. Готовый набор тестов на этот
узел — `kriss-bot/test_photo_buttons.py`.

## Грабли, уже собранные

- **Отдавать `reply_photo`** — Telegram пережмёт результат и обработка станет
  незаметной. Отдавать `reply_document` (для стикера — `reply_sticker`/document PNG).
- **Забыть EXIF-поворот** — фото с телефона вернётся лёжа. В `photo.py` уже
  `exif_transpose`, но если пишешь свою обработку мимо модуля — грабли твои.
- **Тянуть `rembg` во все боты** — образ +200 МБ и RSS +500 МБ на каждый сервис.
  Модуль сам это переживает: без `rembg` запрос «убери фон» отдаёт портретную
  обработку и объясняет, чего не хватает.
- **Ставить AI-перерисовку условием работы** — Cloudflare может не ответить или
  упереться в дневной лимит. Фильтры и фон обязаны работать всегда.

## Ключи (опционально, для AI-перерисовки)

Регистрация: dash.cloudflare.com → бесплатный аккаунт → Workers AI. Бесплатно
10 000 нейронов/день (сотни картинок 512×512), карта не нужна.

```
CF_ACCOUNT_ID=...    # Dashboard → Workers & Pages → Account ID
CF_API_TOKEN=...     # My Profile → API Tokens → шаблон Workers AI (Read/Run)
```
Кладутся в Railway-переменные бота или в Redis: `office:secrets:cf_account_id`,
`office:secrets:cf_api_token` (модуль читает env, потом Redis — как elevenlabs).

## Проверка перед деплоем

```
python scripts/photo_probe.py фото.jpg --out /tmp/probe
```
Гоняет все 13 операций на реальном файле, печатает время/вес/ошибки и
показывает, подключены ли `rembg` и ключи Cloudflare. Выход ≠ 0 — не деплоить.
