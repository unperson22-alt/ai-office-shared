# Схема `lessons.json`

Один файл, два вида записей. Различает поле `kind`.

Зачем один файл, а не два: Силли и так читает `lessons.json` первым делом, а
второе хранилище — это вторая вещь, которая молча разойдётся с реальностью.
Разделение делаем полями, а не файлами.

## Общие поля

| поле | | |
|---|---|---|
| `id` | int | сквозная нумерация по всему файлу |
| `date` | `YYYY-MM-DD` | |
| `kind` | `lesson` \| `decision` | **отсутствует = `lesson`** (так живут записи #1–110) |
| `bot`, `layer` | str | где это |
| `title` | str | одна фраза, по-английски — см. «Язык» |
| `tag` | str | для выборки по теме |
| `anchors` | list[str] | `путь/файл.py:symbol` — см. ниже |
| `posted_to_group` | bool | публикацией занимается `publish_pending_lessons` |

## Язык

`title` — **по-английски, без исключений**: так написаны все 118 записей, и это
единственное, что проверяется тестом (`test_lesson_language.py`). Запись #118
приехала 23.08.2026 с русским заголовком — ровно потому, что автор писал в тот
момент коммит и тело PR, а они здесь русские. Теперь это ловится за миллисекунды.

Тело (`symptom`, `root_cause`, `why_architecture`, `fix`, `prevention`,
`decision`, `why`) — тоже по-английски. Это соглашение, а не гейт: записи #105 и
#106 от 21.08 написаны по-русски целиком, и переписывать их задним числом — та же
подгонка архива под проверку, из-за которой не тронуты `cause` в #31–40.
Порог по доле кириллицы отделил бы их от цитат только вместе с половиной живых
записей, поэтому здесь правило держится глазами, а не тестом.

Репозиторий двуязычен по областям, и это намеренно: код, докстринги, коммиты
и PR — русские, архив уроков — английский. Граница проходит по файлу, а не по
задаче, поэтому проверять её надо, открыв файл, а не вспоминая, на каком языке
шла работа.

**Цитата остаётся на своём языке.** Строка лога, текст сообщения в чат, фраза,
которую написала модель, — приводятся дословно; перевод цитаты делает её
бесполезной как улику. Кириллица внутри английской записи — это, как правило,
именно цитата (см. #114, #115, #117), и трогать её не надо.

## `kind: "lesson"` — что сломалось

Поля прежние, порядок и смысл не меняются:
`symptom` → что увидел пользователь, `root_cause` → что именно сломалось,
`why_architecture` → почему архитектура это допустила, `fix` → что изменено,
`status`, `prevention` → как не повторить, `cause`.

Записи **#31–40** писались по ранней схеме и несут `cause` вместо `root_cause`.
Так и оставлено: переписывать десять исторических записей ради формы —
подгонка архива под проверку. Тест принимает любое из двух полей.

## `kind: "decision"` — почему сделано так

Ничего не ломалось. Записывается ВЫБОР.

| поле | |
|---|---|
| `decision` | что выбрано, одним утверждением |
| `why` | почему именно так |
| `rejected` | какие варианты отвергнуты и чем именно они хуже |
| `revisit_if` | при каком новом факте решение стоит пересмотреть (необязательно) |

Полей `symptom`/`root_cause`/`fix` у решения НЕТ — это и есть то самое
разделение «почему так» и «что чинили».

## `anchors` — привязка к коду

Формат `путь/от/корня.py:имя_символа`, например
`agents/coder.py:file_shrink_guard`. Символ ищется как определение верхнего
уровня (`def`/`async def`/`class`) или как присваивание константы.

`tests/test_lesson_anchors.py` проверяет, что каждый якорь указывает на живой
код. Переименовали функцию, о которой есть запись, — CI краснеет и заставляет
либо поправить запись, либо осознанно её закрыть.

Проверяется НЕ «написал ли ты запись» (такое правило вырождается в турникет), а
«не сгнила ли написанная». Ловим ровно тот отказ, который уже случался: правило
на CLAUDE — СТАРТ описывало механизм, которого в проде не было, и сессии
месяцами искали несуществующее.

## Когда запись обязательна

Только два случая:

1. правка меняет **инвариант** из `CLAUDE.md`;
2. правка **противоречит** уже записанному решению.

Всё остальное живёт в коммит-мессадже. Требовать «почему» на каждую правку —
значит получить полсотни записей «переименовал для ясности», после которых
архив перестают читать первым. Правило, убивающее собственную цель, хуже
отсутствующего.
